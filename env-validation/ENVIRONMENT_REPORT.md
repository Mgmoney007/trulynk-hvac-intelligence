## What works for the full project

Search through WebSearch and Firecrawl. Direct fetch through curl, Node, and Python. Rendering, mobile emulation, screenshots, and JSON-LD/tel/mailto extraction through Node Playwright. Firecrawl as a fallback for bot-protected sites. Report generation in all three formats.

## Gaps and required changes

1. **Bot-protected sites (Hetter mobile).** Use Firecrawl scrape (`mobile: true`) as the automatic fallback when Playwright gets a 403 or a challenge page. No config change needed. Firecrawl credits are consumed per call, so budget about 2-4 credits per company.
2. **Overlays in screenshots.** The scraper should dismiss cookie banners and chat widgets (click Reject/Close, or hide known overlay selectors) before capturing. This is a code change, not a configuration change.
3. **Emails are rarely on homepages.** None of the three homepages published an email. The full run should check `/contact`-style pages and report "not published" instead of guessing.
4. **Call-tracking numbers.** Treat schema/footer numbers as canonical and keep every observed number with its source.
5. **Apify** is not configured. It isn't needed given Firecrawl. Adding it would require connecting an Apify MCP server with the user's own token. Not done.
6. **Python Playwright** is not installed. It isn't needed because Node Playwright works. Do not `pip install playwright` / `playwright install`, since that would download a mismatched browser.
7. **Persistence.** The container is ephemeral. Deliverables must be committed and pushed to survive.

## Not tested / unverified

Rate limits or blocking at scale (only 3 sites tested). Firecrawl credit balance (no balance endpoint was checked). Pull request creation (intentionally not done).
